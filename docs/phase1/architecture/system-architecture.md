# 第一阶段系统逻辑架构（基线草案）

- **状态**：逻辑架构草案；接口协议和部署拓扑待 01-03/01-04 后续细化
- **版本**：0.1
- **日期**：2026-11-04
- **关联任务**：01-03
- **需求依据**：[系统需求规格](../requirements/system-requirements.md)、[项目需求基线](../requirements/requirements-baseline.md)
- **适用边界**：FFF、Cartesian 床身移动式参考打印机的 SIL 优先系统。

## 1. 架构原则

- 系统上下文与主数据流图：[system-context.mmd](system-context.mmd)。
- 接口逻辑契约：[接口控制文档（ICD）](interface-control.md)。

1. 先建立可在纯软件环境运行的端到端闭环，真实硬件不是 SIL 启动条件。
2. 控制逻辑通过设备抽象接口访问运动、温度、限位和风扇能力；虚拟后端是第一阶段默认执行后端。
3. 主机负责作业编排和用户交互；实时控制核心负责命令执行、运动/挤出协调、温控和故障状态。
4. 接口先定义语义、责任、错误和状态，再决定传输协议、序列化格式及具体实现。
5. G-code 命令子集、温度/运动参数、时序阈值和物理器件型号不得在本架构草案中臆定。
6. 所有安全相关故障必须有明确状态和可观测事件；SIL 结果不能替代硬件保护验证。

| 层/组件 | 主要责任 | 输入 | 输出 | 当前边界 |
|---|---|---|---|---|
| 操作界面（UI） | 设备选择、作业控制、状态/告警展示 | 用户操作、主机状态 | 用户命令、视图模型 | UI 技术栈待 01-04 选择 |
| 主机应用服务 | 设备会话、作业队列、任务生命周期、配置、日志 | UI 请求、设备事件、作业文件 | 控制请求、任务状态、遥测 | 具体进程/服务划分待定 |

| 固件命令与任务控制 | 命令解析、任务状态机、权限/前置条件检查 | G-code/控制命令 | 运动/过程指令、状态/错误事件 | 命令子集由 ICD 冻结 |
| 运动与挤出控制 | 坐标解释、轨迹规划、轴与 E 轴同步、边界检查 | 运动段、挤出指令、限位状态 | 运动事件/目标、执行状态 | 速度/加速度/步进参数待机械与固件分析 |
| 温控与设备管理 | 温度采样、加热控制、风扇控制、传感器合理性检查 | 温度读数、目标/控制命令 | 加热输出、温度/故障事件 | 温度阈值与 PID 参数待器件和模型依据 |
| 安全状态管理 | 故障锁存、动作拒绝、复位条件和故障记录 | 各子系统故障、通信/看门狗事件 | 受限状态、停止/关闭请求、告警 | 安全策略需 01-05 深化 |
| HAL / 虚拟设备后端 | 抽象 GPIO/定时器/ADC/PWM/步进/限位/温度等能力 | 固件控制请求 | 虚拟输入/输出与事件 | 第一阶段使用虚拟实现；真实 HAL 不在当前 SIL 范围 |
| 仿真模型与场景执行器 | 运动/热对象近似、时间推进、故障注入、场景重放 | 控制输出、场景配置 | 传感器反馈、故障、测试观测 | 模型保真度分级，禁止过度推断 |
| CI 与验证工具 | 构建、静态检查、单元/集成/SIL 测试、报告归档 | 源码、配置、测试场景 | 测试结果、日志、制品 | 工具链和执行平台待选型 |

## 3. 数据流与控制流

### 3.1 作业控制主路径

操作者 → UI → 主机应用服务 → 作业校验/队列 → 设备通信适配层 → 固件任务控制 → 命令解释与运动/温控子系统 → HAL → 虚拟设备模型。

反馈路径反向返回：虚拟设备模型/HAL → 固件状态与故障事件 → 设备通信适配层 → 主机状态模型 → UI/日志/测试断言。

### 3.2 G-code 执行路径

1. 作业输入组件读取模型或 G-code 文件。
2. 对 G-code 执行文件级校验，并绑定作业 ID、文件摘要和设备能力要求。
3. 主机在设备连接后提交作业；固件对支持命令、参数和当前状态进行校验。
4. 运动命令进入运动规划；挤出命令与路径段建立同步关系。
5. 温控/风扇等过程命令进入设备管理子系统。
6. 执行事件、位置/温度观测、任务进度和故障返回主机。
7. 作业结束、取消或故障后，主机保存结果和日志。

文件级校验不等同固件执行许可；固件必须再次校验命令和当前状态。主机已发送数据不等于设备已执行。

### 3.3 SIL 反馈闭环

仿真执行器启动虚拟设备后端；控制核心产生虚拟步进/加热输出；运动/热模型更新虚拟状态；模型输出位置、温度和限位输入；控制核心采样并调整下一步输出。测试执行器可注入传感器异常、卡滞、通信丢失、过温等场景。

## 4. 故障域与隔离边界

| 故障域 | 典型故障 | 应隔离/上报的边界 | 关联需求 |
|---|---|---|---|
| UI/客户端 | 关闭、重复点击、显示过期 | 不得绕过主机/固件状态校验；显示连接状态与数据时间 | SYS-010、SYS-013 |
| 主机服务 | 崩溃、任务队列丢失、状态不同步 | 会话失效/状态未知；不得声称设备已完成未确认动作 | SYS-002、SYS-009、SYS-013 |
| 通信链路 | 断连、延迟、乱序、重复消息 | 消息关联/确认/超时语义由 ICD 定义；状态未知时禁止盲目续跑 | SYS-002、SYS-013 |
| 固件控制核心 | 非法命令、任务卡死、状态机错误 | 故障锁存、拒绝新动作、可追溯错误 | SYS-003、SYS-009、SYS-014 |
| 运动子系统 | 越界、限位未触发、轨迹异常 | 运动命令拒绝/故障上报；不把规划成功当作执行成功 | SYS-005、SYS-006 |
| 温控子系统 | 传感器无效、升温失败、过温 | 关闭虚拟加热输出、进入故障状态 | SYS-007、SYS-008、SYS-014 |
| 虚拟设备/仿真模型 | 数值发散、模型停止推进、时间异常 | 标记仿真失效；不得把模型异常当作被测固件故障 | SYS-015、NFR-001 |
| CI/测试 | 测试未执行、报告缺失、环境漂移 | 测试状态标记为阻塞/无效，不可默认通过 | NFR-001、NFR-002 |

## 6. 架构约束与待决事项

- 本文件定义逻辑责任和接口方向，不指定 TCP/串口/USB/CAN 等具体传输方案。
- 本文件不指定 JSON、二进制帧、RPC 或消息队列等序列化/交互机制。
- 不指定 MCU、控制板、操作系统、编程语言、框架、UI 技术和 CI 服务。
- G-code 命令支持集合、坐标单位/模式细节、命令确认语义、错误码和超时值由 ICD/软件选型阶段确定。
- 暂停/取消时运动队列、挤出和加热的处理规则必须结合安全分析确定。
- 虚拟 HAL 与物理 HAL 的接口应可替换，但当前不宣称已完成任何物理硬件适配。
