## 1. 目的与适用边界

定义主机、固件控制核心、HAL、虚拟设备模型、仿真执行器和测试框架之间必须保持一致的逻辑接口语义。本文不是线缆接线图、寄存器映射、网络协议规范或已冻结的 API 定义。

## 2. 通用接口规则

1. 每条请求和响应均应能关联设备会话；任务相关消息还应能关联任务 ID。
2. 请求结果至少区分：已接受、已拒绝、执行中、已完成、失败/未知。仅“已发送”不能等同“已执行”。
3. 错误响应应包含稳定错误类别、可读说明、关联请求/任务标识及是否允许重试；具体错误码表待定。
4. 状态观测应带有采样/产生时间或单调序号，以便识别过期、乱序和重复更新；具体时钟源待定。
5. 设备能力必须显式声明；主机不得假设设备支持未声明的命令或功能。
6. 对可能改变运动、加热或任务状态的请求，固件必须重新检查当前状态与前置条件。
7. 连接丢失、超时或响应不确定时，调用方必须将执行结果标记为未知，不得自行推断成功。
8. 接口版本变化必须说明兼容策略；破坏性变更需更新需求追踪、测试语料和版本记录。

## 3. 逻辑接口契约

### IF-001：用户界面与主机应用

- **方向**：UI ↔ 主机应用服务
- **操作类别**：读取设备列表/能力/状态；连接/断开；提交作业；开始/暂停/恢复/取消；读取日志和故障。
- **事件类别**：连接状态变化、任务状态变化、遥测更新、故障告警。
- **一致性要求**：UI 只显示主机确认的状态；连接断开后显示状态未知/断开；非法状态操作返回明确拒绝。
- **待定**：API 风格、认证/授权模型、刷新策略、事件推送方式。

### IF-002：主机应用与设备通信适配层

- **方向**：主机应用 ↔ 设备通信适配层
- **操作类别**：建立会话、读取能力、发送命令/作业块、请求状态、关闭会话。
- **事件类别**：设备上线/离线、响应、遥测、错误、超时。
- **一致性要求**：请求与响应可关联；重复消息可识别；断连后不得把未确认请求记为成功。
- **待定**：传输方式、消息 framing、序列化格式、超时/重连值、流控和认证。

### IF-003：作业服务与固件任务控制

- **方向**：主机作业服务 → 固件任务控制；任务事件反向返回。
- **请求类别**：提交作业元数据/内容、校验、开始、暂停、恢复、取消、查询任务。
- **必需标识**：设备会话 ID、任务 ID、作业内容摘要或等价完整性标识。
- **响应类别**：接受/拒绝、当前任务状态、执行事件、完成/取消/故障终态。
- **一致性要求**：同一设备最多一个活动作业；重复提交和重复控制请求必须有明确幂等/拒绝规则；终态不得互相冒充。
- **待定**：作业传输分块、校验算法、队列策略、暂停安全点和恢复语义。

### IF-004：G-code 解析器与运动/挤出控制

- **方向**：命令解析器 → 运动与挤出控制
- **输入类别**：线性/其他受支持运动命令、坐标模式、单位模式、进给参数、挤出目标。
- **输出类别**：已验证的运动段、挤出段、拒绝原因和执行事件。
- **一致性要求**：解析器输出必须是显式单位和坐标语义；运动控制再次检查软限位和当前状态；不支持的命令不得静默忽略。
- **待定**：G-code 方言子集、参数合法范围、坐标系定义、前瞻/缓冲策略、错误码。

### IF-005：命令控制与温控/设备管理

- **方向**：固件命令控制 → 温控/设备管理；遥测和故障反向返回。
- **输入类别**：温度目标请求、加热使能/关闭、风扇控制。
- **输出类别**：温度观测、输出状态、传感器状态、温控故障。
- **一致性要求**：目标值和输出请求均须经过范围/状态校验；传感器无效或致命故障时按安全策略关闭虚拟加热输出并锁存故障。
- **待定**：温度单位、允许范围、传感器类型、采样周期、控制算法和保护阈值。

### IF-006：控制核心与 HAL

- **方向**：固件控制核心 ↔ HAL
- **能力类别**：轴/步进事件输出、限位输入、温度采样、加热/风扇输出、单调时间源、故障通知。
- **一致性要求**：上层逻辑不得依赖具体 MCU 寄存器或板卡引脚；HAL 返回明确能力/错误；虚拟实现与未来物理实现遵循同一语义。
- **待定**：具体 HAL API、任务上下文/并发模型、实时性预算、物理板卡映射。

### IF-007：HAL 与虚拟设备模型

- **方向**：HAL ↔ 虚拟设备模型
- **输入类别**：虚拟步进/加热/风扇输出、场景时间推进。
- **输出类别**：轴位置、温度、限位、传感器状态和模型故障。
- **一致性要求**：模型输入/输出具备可重复的更新顺序；模型异常必须与被测固件故障区分；场景参数和模型版本可追溯。
- **待定**：模型时间步、运动/热参数、求解算法、模型误差和保真度等级。

### IF-008：仿真执行器与测试框架

- **方向**：仿真执行器 ↔ 测试框架
- **操作类别**：加载场景、启动/停止、推进虚拟时间、注入故障、读取观测、导出报告。
- **一致性要求**：测试报告记录源码 commit、场景配置、模型版本、输入、预期与实际结果；未执行/跳过/阻塞不得标为通过。
- **待定**：场景文件格式、测试 runner、随机种子接口和报告格式。

### IF-009：CI 与构建/测试工具

- **方向**：CI 编排 → 构建、静态检查、单元/集成/SIL 测试工具
- **输入类别**：代码版本、依赖锁定文件、配置和测试选择。
- **输出类别**：构建制品、测试结果、日志、覆盖率/静态检查报告。
- **一致性要求**：失败必须使对应检查失败；测试未执行不能当作通过；制品关联源码 commit。
- **待定**：CI 服务、容器/虚拟环境、缓存策略和制品保留策略。

## 4. 通用消息字段（逻辑字段，不代表线协议）

| 字段 | 用途 | 必需性/约束 |
|---|---|---|
| message_id | 唯一识别一次请求/事件 | 请求/响应关联必需；生成策略待定 |
| session_id | 识别设备会话 | 设备通信消息必需 |
| task_id | 识别打印任务 | 任务相关消息必需 |
| interface_version | 识别接口语义版本 | 对外接口必需 |
| sequence | 识别事件顺序/重复 | 事件流建议必需；单调性范围待定 |
| timestamp | 记录产生/采样时间 | 观测与日志必需；时钟源待定 |
| status | 请求或任务状态 | 状态响应必需；枚举由接口实现统一 |
| error | 错误类别和上下文 | 失败/拒绝时必需 |
| payload | 具体命令、能力或观测数据 | 按消息类型定义 schema |

## 5. 错误类别草案

- INVALID_ARGUMENT：参数格式或范围非法。
- UNSUPPORTED_OPERATION：设备/固件未声明支持该操作。
- INVALID_STATE：当前设备/任务状态不允许该操作。
- LIMIT_VIOLATION：运动或过程请求违反配置边界。
- DEVICE_FAULT：设备子系统报告故障。
- COMMUNICATION_TIMEOUT：请求在定义时限内没有得到确认。
- CONNECTION_LOST：会话断开，执行结果可能未知。
- INTERNAL_ERROR：未分类的内部失败，必须附带关联 ID 和日志上下文。

以上为逻辑错误类别，不是已冻结的线上错误码或协议枚举。


## 6.1 跨接口一致性契约（语义层）

下列规则用于避免各模块对同一事件作出不同解释；不规定具体传输协议或数值预算。

### 6.1.1 请求、确认与执行结果

| 语义阶段 | 含义 | 调用方可作出的结论 |
|---|---|---|
| Sent | 请求已交给本地通信适配层 | 仅表示本地发送动作发生，不代表设备收到 |
| Received | 对端已接收并识别请求 | 不代表请求已获准或开始执行 |
| Accepted | 对端已校验并接受请求 | 请求进入后续处理；不代表执行完成 |
| Rejected | 对端拒绝请求 | 必须提供稳定错误类别；不得产生请求所要求的动作 |
| InProgress | 对端报告执行正在进行 | 可显示执行中；不得显示完成 |
| Completed | 对端确认请求对应动作已完成 | 仅对该请求/任务范围成立 |
| Failed | 对端确认执行失败 | 必须关联错误与已知部分执行状态 |
| Unknown | 调用方无法确认请求最终结果 | 不得推断成功；不得盲目重发非幂等动作 |

响应丢失或超时可能发生在对端已经执行之后。调用方应先查询请求/任务状态或重新同步会话；只有接口明确声明幂等且使用相同幂等标识时，才允许安全重试。不得仅因本地超时就推断对端未执行。

### 6.1.2 标识、顺序与重复消息

- `message_id` 在其定义的命名空间内唯一；请求与响应必须可关联。
- `session_id` 标识一次设备会话。重连建立新会话代际时，旧会话未完成请求不得自动迁移为新会话的成功结果。
- `task_id` 标识一次作业生命周期；同一设备的活动任务唯一性由固件任务控制端最终裁决。
- `sequence` 必须明确其作用域（至少区分会话、任务或事件流）；接收方应能检测重复与可识别的乱序。具体序号宽度、回绕和缓存窗口待协议选型确定。
- 接收方对重复请求必须按接口定义返回原结果、拒绝重复，或执行显式幂等处理；不得无意重复产生运动/加热副作用。
- 时间戳用于记录和诊断；跨时钟域不得仅按时间戳推断严格先后，必要时使用同一序号域或显式因果关联。

### 6.1.3 单位、坐标与数值有效性

- 每种物理量必须在接口 schema 中声明单位；禁止依赖未声明的默认单位或仅靠字段名猜测。
- 运动数据必须声明坐标系、轴标识、绝对/相对语义及单位模式；E 轴必须说明其采用的挤出量语义。
- 坐标变换、单位换算和边界检查应在明确的责任组件执行；解析器完成语法解析不等于运动控制已批准执行。
- 温度观测/目标必须声明温标；时间量必须声明时间单位及所属时钟域。
- 非有限数、溢出、缺失字段、未知枚举和超出已配置边界的值必须显式拒绝，不得静默截断或替换为默认值。
- 轴正方向、机器原点、有效行程、步进换算和热控量程仍须由机械/硬件/固件设计依据冻结，不在本文件中臆定。

### 6.1.4 超时、重试与重连

- 超时是调用方未在规定预算内获得所需确认，不等同于对端执行失败。
- 超时预算必须区分连接建立、请求确认、执行完成、遥测新鲜度和心跳/会话存活等语义；具体值由 01-04 平台评估和测量后确定。
- 重试策略必须逐操作声明：是否幂等、最大重试/退避策略、是否先查询状态；运动、挤出、加热和任务控制不得套用统一盲重试。
- 连接恢复后，主机必须重新读取能力与设备/任务状态，标记旧遥测过期，并处理未决请求的未知结果。
- 在状态重新同步完成前，不得自动续跑可能产生运动或加热副作用的未决命令。

### 6.1.5 任务状态与安全责任

- 主机可发起任务请求，但固件任务控制端是设备侧任务状态转换的最终裁决者；UI 只呈现主机已确认或明确标为未知的状态。
- 接受暂停请求不等于已经暂停；只有收到暂停已生效的状态/事件，才能报告 Paused。
- 接受取消请求不等于已取消；只有停止条件满足且任务终态确认后，才能报告 Cancelled。
- 发生致命故障时，安全状态管理负责锁存故障并协调相关子系统拒绝后续动作；清故障与复位不能由普通开始/恢复请求隐式触发。
- 暂停安全点、取消时队列清理、加热保持/关闭策略和故障复位条件须由 01-05 安全概念与 05 固件设计共同确定。

### 6.1.6 遥测与状态新鲜度

- 遥测应携带采样/产生时间或同一事件流的单调序号，并标明数据来源。
- 主机必须区分当前值、最后已知值和未知值；连接丢失或超过后续定义的新鲜度预算时，不得把最后已知值伪装成实时值。
- 任务进度必须基于设备侧执行确认或定义明确的执行观测；已发送字节数、已排队命令数不得冒充已执行进度。
- 具体刷新频率、过期阈值与缓存策略由 01-04 结合 UI/通信方案确定。

### 6.1.7 接口责任与错误传播矩阵

| 接口 | 契约责任方 | 必须校验/保证 | 错误传播要求 |
|---|---|---|---|
| IF-001 | HOST | 用户操作状态合法性、展示数据来源/新鲜度 | 返回拒绝原因；未知状态显式显示 |
| IF-002 | COMM | 会话、请求关联、超时、断连、重复/乱序检测 | 区分超时、断连、协议错误和未知执行结果 |
| IF-003 | TASK（状态裁决）；HOST（请求一致性） | 任务唯一性、状态转换、幂等/重复请求策略 | 任务事件带 task_id；拒绝/终态可追踪 |
| IF-004 | PARSE（语义解析）；MOTION（执行前复核） | 语法、单位/模式声明、数值与工作空间边界 | 解析错误与运动拒绝分开报告 |
| IF-005 | THERMAL；SAFETY 对故障策略有最终约束 | 目标值合法性、传感器有效性、故障状态检查 | 设备故障向 TASK/SAFETY 上报并记录输出状态 |
| IF-006 | HAL | 能力声明、输入/输出单位、调用上下文与错误 | 不暴露硬件寄存器细节；错误不静默吞掉 |
| IF-007 | VDEV（模型行为）；HAL（抽象一致性） | 确定性更新顺序、模型版本、输入输出单位 | 模型异常单独标识，不混同固件故障 |
| IF-008 | SIM、TEST | 场景配置、虚拟时间、故障注入与结果记录 | 场景失败/无效与被测软件失败区分 |
| IF-009 | CI | 版本、依赖、构建/测试状态与制品关联 | 失败、跳过、未执行分别报告，不可折算为通过 |

## 7. 接口冻结前检查项

- 每个接口有提供方、使用方、责任、请求/响应/事件和错误语义。
- 状态转换、并发、重复请求、超时、重连和幂等规则明确。
- 单位、坐标系、数值范围、时间基准和版本兼容策略明确。
- 安全相关命令具备前置条件、拒绝规则和故障响应。
- 至少有正向、非法输入、边界、超时/断连和故障注入测试。
- 协议/工具链选择完成后，补充具体 schema、示例帧和版本策略。
