## 1. 组件简称

| 简称 | 逻辑组件 | 责任边界 |
|---|---|---|
| UI | 用户界面/客户端 | 用户操作、状态与告警呈现 |
| HOST | 主机应用服务 | 会话、任务编排、状态汇总、配置与日志 |
| JOB | 作业输入与切片集成 | 文件导入、校验、作业元数据与内容交付 |
| COMM | 设备通信适配层 | 请求/响应关联、传输、超时、断连与重连 |
| TASK | 固件命令与任务控制 | 命令分派、任务状态机、前置条件与故障锁存协调 |
| PARSE | G-code 解析器 | 命令语法、模式与参数语义解释 |
| MOTION | 运动与挤出控制 | 轨迹、边界检查、归零/限位协调 |
| THERMAL | 温控与设备管理 | 温度观测、输出控制、传感器诊断 |
| SAFETY | 安全状态管理 | 故障状态、动作禁止、复位条件协调 |
| HAL | 硬件抽象层 | 统一设备能力接口 |
| VDEV | 虚拟设备模型 | 轴、限位、温度、加热与时间响应 |
| SIM | 仿真场景执行器 | 场景生命周期、虚拟时间与故障注入 |
| TEST | 自动化测试框架 | 断言、报告与证据归档 |
| CI | 构建与持续集成 | 构建、静态检查、测试编排与制品关联 |
| LOG | 日志/状态记录 | 事件、遥测、故障和执行证据持久化 |

## 4. 覆盖审查结果与待关闭项

### 4.1 设计追踪覆盖

- SYS-001 至 SYS-015 均至少映射到一个主责组件和一个逻辑接口。
- SIL-001 至 SIL-014 均映射到 SYS、组件和接口；当前属于设计追踪覆盖，不代表测试已经实现或通过。
- IF-001 至 IF-009 均至少被一个系统需求或 SIL 场景引用。
- 追踪关系允许一个需求跨多个组件/接口；表中“主责组件”表示逻辑责任，不等同代码目录或进程部署。

### 4.3 结论

当前架构在逻辑层面实现了 SYS/SIL 到组件和 IF-001 至 IF-009 的全覆盖；请求账本、设备端裁决、事件发布与重连同步的职责已进一步分配，见[请求账本责任矩阵](request-ledger-responsibility-matrix.md)；请求载荷规范化与幂等指纹逻辑规则已形成，见[请求载荷规范化规则](request-payload-canonicalization.md)；设备侧持久化阶段、崩溃窗口和恢复裁决另见[请求账本持久化与崩溃恢复契约](request-ledger-persistence-and-recovery.md)。接口的单位/坐标、顺序/幂等、会话恢复、任务暂停取消、命令确认和时序预算仍未冻结。因此 01-03 继续保持“正在进行中”，不得把追踪矩阵完成误判为接口冻结或实现验收。
