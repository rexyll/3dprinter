- **适用边界**：第一阶段 FFF / Cartesian 床身移动式参考打印机的软件在环（SIL）系统；不构成实物制造规格或安全认证文件。

## 1. 目的与需求层级

本文件把已批准的项目范围和现有 FR/NFR 转换为可检查的系统行为与验收追踪条目。FR/NFR 是项目级需求，权威定义仍位于需求基线；SYS 是本文件定义的系统级行为要求；SIL 是端到端仿真验收场景。SYS 不取代 FR/NFR。若两者冲突，先登记问题并修订权威需求，不得由实现代码自行决定。

## 2. 系统边界与参与者

### 2.1 系统内逻辑组件

1. **控制固件/控制核心**：解释已声明支持的运动与过程命令，维护设备状态，协调运动、挤出、温控和故障处理。
2. **虚拟硬件层**：提供虚拟轴/步进执行器、限位输入、温度传感器、加热输出、风扇及时间源等可替换接口。
3. **主机服务**：连接设备、提交任务、管理任务生命周期、收集状态和日志。
4. **用户界面/客户端**：显示连接、设备状态、任务进度和故障，并提交用户操作。
5. **G-code/作业输入**：提供切片生成或经校验的样例作业文件；第一阶段不要求自研完整切片算法。
6. **仿真编排与测试**：创建场景、控制虚拟时间/故障输入、采集结果并生成报告。

组件部署方式、语言、进程边界、具体通信协议和 MCU 型号均留待 01-03/01-04 决定。

### 2.2 外部参与者

- 操作者：连接设备、选择作业、启动/暂停/恢复/取消任务、查看状态和故障。
- 自动化测试执行器：启动仿真场景、发送输入、注入故障、检查输出。
- 仿真设备模型：响应控制命令并产生位置、温度、限位和故障观测。

### 2.3 明确排除

- 未经独立安全设计与授权的真实电机、加热器或电源驱动。
- 真实打印质量、实物尺寸精度、长期可靠性和认证符合性证明。
- 多喷头、多材料、自动换料及其他增材制造工艺。

## 4. 任务生命周期与状态语义

下列状态是需求级逻辑模型，最终事件名、API、并发规则和协议编码由 01-03 ICD 定义。

### 4.1 建议状态

- **空闲（Idle）**：没有活动作业。
- **已连接（Connected）**：主机与设备通信可用，但没有活动作业。
- **校验中（Validating）**：检查作业格式、设备能力和前置条件。
- **就绪（Ready）**：作业已通过校验，可开始。
- **运行中（Running）**：作业命令正在执行。
- **暂停中（Pausing）**：正在处理暂停请求及其安全边界。
- **已暂停（Paused）**：作业停止推进，保留可恢复上下文。
- **取消中（Cancelling）**：正在停止任务并处理待执行动作。
- **已取消（Cancelled）**：任务已终止，不可直接继续原执行上下文。
- **已完成（Completed）**：所有作业命令执行结束且无未处理错误。
- **故障（Fault）**：发生阻止正常运行的故障；须记录故障原因和复位要求。
- **断开（Disconnected）**：主机无法确认设备通信状态。

### 4.2 状态转换要求

1. Idle/Connected → Validating → Ready：作业提交并通过校验。
2. Ready → Running：操作者明确启动，且设备前置条件满足。
3. Running → Pausing → Paused：暂停请求被接受并在定义的安全点生效。
4. Paused → Running：恢复请求被接受，且故障/互锁条件已清除。
5. Ready/Running/Paused → Cancelling → Cancelled：取消请求被接受并完成停止处理。
6. Running → Completed：作业全部执行完成。
7. 任一可运行状态遇到致命故障可转入 Fault；通信状态不可确认时转入 Disconnected 或由架构定义的等价受限状态。
8. Fault 不得通过普通开始/恢复操作直接离开；必须满足故障清除、复位和重新校验条件。
9. 非法转换必须被拒绝并返回明确原因，不得静默修改状态。

### 4.3 状态一致性不变量

- 同一设备最多有一个活动打印任务。
- Paused 不代表运动队列或加热输出可以不受控制地继续推进；暂停时具体保持/关闭策略须由安全设计和 ICD 定义。
- Completed 只能在作业执行完成且没有未处理致命错误时进入。
- Cancelled 与 Fault 不得伪装成 Completed。
- 连接丢失后，主机必须将设备状态标记为未知/断开，不能继续展示为实时可信数据。
- 任务进度必须注明其计算依据（已执行命令、路径段或其他定义），不可仅以已发送字节数冒充实际执行进度。

## 5. 故障与安全响应需求

| 故障场景 | 最低 SIL 可验证响应 | 不可据此宣称 |
|---|---|---|
| 温度传感器断线/短路或读数无效 | 检测无效读数；进入 Fault；虚拟加热输出关闭；记录故障源 | 真实传感器诊断覆盖率或硬件保护有效 |
| 升温失败/温度偏离预期 | 在仿真模型定义的检测条件满足后进入 Fault；关闭虚拟加热输出 | 真实热端升温能力或热失控防护已验证 |
| 过温 | 进入 Fault；禁止继续加热；拒绝新运动/加热任务，按安全策略处理当前运动 | 实物热安全或认证符合性 |
| 限位异常/越界命令 | 拒绝越界命令或进入 Fault；输出原因和位置状态 | 真实限位开关可靠性或机械碰撞安全 |
| 通信中断/超时 | 标记连接状态未知/断开；不把未确认命令记为成功；禁止不安全的自动续跑 | 真实网络可靠性或断电安全 |
| 固件/控制任务无响应 | 仿真监控器识别超时并触发定义的故障处置 | 真实 MCU 看门狗覆盖率 |
| 非法命令/格式错误 | 返回错误，记录上下文；不得静默执行部分未知语义 | 对所有厂商 G-code 方言的兼容性 |

具体超时、温度阈值、温升速率、位置容差和复位条件尚未定义，必须在对应热/运动模型、器件资料和接口设计阶段确定；本表不授权以任意常数实现保护逻辑。

## 10. 需求变更与验收规则

- 需求新增、删除、优先级变化或验收语义变化，必须更新需求基线/本文件，并按贡献指南记录影响；改变已批准参考规格时必须走变更与 ADR 流程。
- P0 必需用例未通过、阻塞或没有可复现报告时，第一阶段 SIL 门禁不得判定通过。
- P1 用例是否成为最终阶段强制门禁，按根 TaskPlan 的第一阶段门禁与集成验收计划执行；不得把 P1 当前未完成描述为 P0 已通过。
- SIL 通过只证明指定版本、配置和仿真模型下的软件行为符合这些验收断言；不证明真实硬件安全、认证、打印精度或材料工艺窗口。
- 本文件中逻辑状态、故障响应和验收用例是需求基线；具体协议、超时、阈值和并发规则需在后续 ICD/安全设计中冻结。
